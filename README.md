# Development container base

Builds and release publication run on the Mini through `build.sh`, under the shared watchdog. There is no GitHub-hosted build workflow. A local build loads the named ARM64 image by default; `--platform=linux/amd64` selects a local AMD64 qualification build before release. Publication always includes both architectures; `--publish` is an explicit release action that requires a clean, reviewed revision and registry authentication, builds ARM64 and AMD64 through the Mini's existing builder, and publishes the exact tag plus `latest`. Consumers pin the published digest rather than following `latest`. The script never prunes images or unrelated caches.

Public Node TLS uses OpenSSL's distribution trust bundle, not Node's independently bundled roots. The image installs the CA package, applies `configure-platform-trust.py` before dependency downloads, and uses Debian’s own CA configuration to rebuild both the bundle and hashed directory so an alternate lookup cannot restore an excluded root. The helper is a temporary, exact-identity guard for incident149555, not a replacement public root program. Remove that guard only after the minimum supported distro bundle independently excludes the affected roots. Rebuild images when the distro trust package changes; a Mac host update does not update a container.

Preserve `--use-openssl-ca` whenever a project adds options to `NODE_OPTIONS`. Keep private service CAs scoped to that service's verified client. Do not union an old public bundle back into platform trust or disable certificate/hostname verification.

Verify a locally built image on the Mini with `docker run --rm --network none -v "$PWD:/verification:ro" devcontainer-base:<tag> python3 -m unittest discover -s /verification -p "test_*.py" -v` and the same command ending in `node /verification/verify-node-trust.mjs`. The Node check verifies the default exclusive CA selection and incident identities, then exercises acceptance and rejection with generated local certificates; it contacts no external service and cleans up its listeners and files.

`scoped-system-trust.mjs` gives unprivileged Linux builders and non-Debian Node images a filtered copy of the maintained system bundle without modifying that store. It removes only the exact incident identities and supplies an empty alternate directory. The caller must set `SSL_CERT_FILE` and `SSL_CERT_DIR` to its returned paths, select `--use-openssl-ca` and explicitly preload its generated `register.mjs` with `--import`, reject additive CA overrides and verification-disable inputs, and preserve these options in later processes. This startup module uses Node’s maintained `tls.setDefaultCACertificates` API to replace the default anchor set, including any independently compiled CA path; it is not activated when the reusable helper is imported. Node must support that API. Worker-thread policy is per thread, so qualify inheritance and any explicit worker-option overrides. Keep private database CAs scoped to their existing clients. This does not provide Apple platform evaluation or configure a Worker’s edge runtime.

Bootstrap consumers pin the exact source commit and SHA-256 before execution. Fetch the public helper without credentials; a compromised transport must fail the content check before any code executes or dependency credentials are exposed. Docker consumers may use BuildKit’s checksum-verified remote `ADD`. Never fetch a mutable `main` helper or run an unchecked response. The image’s existing local Node fixture now also exercises scoped filtering and the selected/unselected-root handshake.

For bootstrap, capture the inherited `NODE_OPTIONS` as data in `NODE_TRUST_INHERITED_OPTIONS` and clear `NODE_OPTIONS` before executing even the verified preparer: `--require` preloads run before `--import`. The helper accepts only the declared memory, stack-trace, source-map, warning and exclusive-OpenSSL options; unsupported options fail rather than being silently dropped. Reject extra/system CA and verification-disable environment overrides before credential-bearing work. Add any genuinely needed startup option deliberately with coverage instead of allowing arbitrary preloads.
